# Contributing to Kittora

Thanks for wanting to contribute! These are the general guidelines for all repositories under the Kittora organization.

## Before you start

1. Check [open issues](../../issues) to avoid duplicate work.
2. For large changes, open an issue first to discuss the approach before writing code.
3. Read the [Code of Conduct](CODE_OF_CONDUCT.md).

## Workflow

1. Fork the repository.
2. Create a descriptive branch: `feature/short-name` or `fix/short-name`.
3. Make small, clear commits.
4. Make sure the project builds/runs locally before opening the PR.
5. Open a Pull Request using the provided template, describing what changes and why.

## Code style

- Python: follow [PEP 8](https://peps.python.org/pep-0008/) where reasonable.
- Clear, descriptive variable and function names.
- Avoid adding new dependencies without justifying them in the PR.

## Reporting bugs

Use the "Bug report" template and include:
- Steps to reproduce
- Expected vs. actual behavior
- OS and version
- Logs or screenshots if applicable

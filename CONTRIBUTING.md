# Contribuir a Kittora / Contributing to Kittora

## 🇪🇸 Español

¡Gracias por tu interés en contribuir! Estas son las pautas generales para todos los repositorios de la organización Kittora.

### Antes de empezar

1. Revisa los [issues abiertos](../../issues) para evitar trabajo duplicado.
2. Para cambios grandes, abre primero un issue para discutir el enfoque antes de escribir código.
3. Lee el [Código de Conducta](CODE_OF_CONDUCT.md).

### Flujo de trabajo

1. Haz un fork del repositorio.
2. Crea una rama descriptiva: `feature/nombre-corto` o `fix/nombre-corto`.
3. Haz commits pequeños y claros (idealmente en inglés, para consistencia del historial).
4. Asegúrate de que el proyecto compile/corra localmente antes de abrir el PR.
5. Abre un Pull Request usando la plantilla proporcionada, describiendo qué cambia y por qué.

### Estilo de código

- Python: sigue [PEP 8](https://peps.python.org/pep-0008/) en la medida de lo posible.
- Nombres de variables y funciones en inglés; comentarios pueden ir en español o inglés.
- Evita dependencias nuevas sin justificarlas en el PR.

### Reportar bugs

Usa la plantilla de "Bug report" e incluye:
- Pasos para reproducir
- Comportamiento esperado vs. lo que ocurrió
- Sistema operativo y versión
- Logs o capturas si aplica

## 🇬🇧 English

Thanks for wanting to contribute! These are the general guidelines for all repositories under the Kittora organization.

### Before you start

1. Check [open issues](../../issues) to avoid duplicate work.
2. For large changes, open an issue first to discuss the approach before writing code.
3. Read the [Code of Conduct](CODE_OF_CONDUCT.md).

### Workflow

1. Fork the repository.
2. Create a descriptive branch: `feature/short-name` or `fix/short-name`.
3. Make small, clear commits (ideally in English, for history consistency).
4. Make sure the project builds/runs locally before opening the PR.
5. Open a Pull Request using the provided template, describing what changes and why.

### Code style

- Python: follow [PEP 8](https://peps.python.org/pep-0008/) where reasonable.
- Variable and function names in English; comments can be in Spanish or English.
- Avoid adding new dependencies without justifying them in the PR.

### Reporting bugs

Use the "Bug report" template and include:
- Steps to reproduce
- Expected vs. actual behavior
- OS and version
- Logs or screenshots if applicable
